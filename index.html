Building a Bangla-first language model from the first byte

Sifat AhmedSyncAura ResearchDhaka, BangladeshStarted 10 October 2026
Abstract

CogNova 3.0 asks whether a small team, on one consumer graphics card, can build a useful language model for Bangla, English and code without starting from someone else's weights. We write the tokenizer, the transformer and the training loop ourselves, and treat every step as an experiment: the expected result is written down first, the run is bounded, and the actual result is recorded next to it, including when it falls short. Six experiments are complete. A 1.33M-parameter reference model trains stably, overfits a tiny batch on purpose, and resumes from a checkpoint with zero numerical difference. Our audit of real Wikipedia text showed what the next model needs: context chunking, stronger cleaning and record-level rights clearance before any real training starts.

§1 Research questions

What we are trying to find out.

Many Bangla language tools today are fine-tuned from models trained mostly on English. CogNova starts from the other end.

RQ1

Can a tokenizer treat Bangla as a first-class script?

Many tokenizers split Bangla into far more tokens than English, which wastes context and compute. We build our own byte-level BPE and measure it on both languages.

RQ2

Can every part of the stack be verified, not just trusted?

Each component is checked against a reference on CPU and GPU before it is used, so later results can be traced to code that is known to be correct.

RQ3

How far does one 6 GB consumer GPU go?

All work runs on a single RTX 3050. We measure memory, time and stability for each step so scaling decisions rest on numbers, not hope.

RQ4

Can training data be clean, traceable and rights-checked?

Every text window keeps its source, revision, licence evidence and byte offsets. Nothing enters training until its rights are actually cleared.

§2 Method

Evidence-gated research.

No experiment moves the project forward on a feeling. Each one follows the same five steps, and the next gate opens only when this one has evidence.

01

Declare

Write the protocol, limits and pass thresholds before running anything.

02

Bound

Cap time, steps, tokens, downloads and memory so a run cannot drift.

03

Run

Execute once, on fixed seeds and fixed splits, with no tuning on held-out data.

04

Compare

Record expected versus actual in a table. Targets are never moved afterwards.

05

Preserve

Hash and keep evidence, so anyone can check exactly what happened.

A passed gate means the engineering works as declared. It is never read as proof of language ability. That needs representative benchmarks, which come later.

§5 Findings

What we learned.

The from-scratch stack is sound

Tokenizer, model and optimizer are verified, numerically stable on a 6 GB GPU, and reproducible to the last bit.

Synthetic data has done its job

It proved the pipeline learns. It cannot teach language, so held-out quality now depends entirely on real data.

Context, not compute, is the first wall

Almost no real article fits in 128 tokens. Windowing works today; a longer context and a tokenizer tuned for Bangla are the real fix.

Rights are the slowest gate

Licence evidence is recorded for every article, but page-history and imported-text exceptions still block training use. We will not skip this.

§6 Limits and open gates

What these results do not show.

Said plainly, so the numbers above are not read as more than they are.

  • No benchmark of real Bangla, English or code ability has been run yet.
  • Held-out sets are tiny (3 texts in T0), so generalisation cannot be judged.
  • The 30-minute sustained GPU and memory test was paused at 5.5 minutes and is not passed.
  • No Wikipedia text is cleared for training; W1 and W2 are audit-only.
  • Windows have no overlap, so meaning across window edges is lost.
  • Trained weights stay private and local. No model is released.
